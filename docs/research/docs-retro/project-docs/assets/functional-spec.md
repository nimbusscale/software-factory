# Functional spec

The functional spec: what the app should do, in the user's terms. Requirements are in GEARS, with
`FR` IDs. It never links to other docs. Other docs, prompts and code point to its IDs.

## F-SEC-1. Terms

The terms a user would recognize, each defined once in plain language.

## F-SEC-2. Limits

Limits that always hold, each with its reason.

## F-SEC-3. <An area of behavior>

One section per area a user would recognize, such as planning a day. Each requirement has its
scenarios under it.

**FR-1.** <Where ...> <While ...> <When ...> The <subject> shall <behavior>.

*Scenario:* Given ..., when ..., then ....
